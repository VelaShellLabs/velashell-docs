# 12 · 安全与威胁模型

> **现状限定**：下面 v1 强度表/威胁缓解表是蓝图目标，不是对当前全部插件运行模式的安全保证。当前仍有 inProcess 插件，`PluginPermissionGate` 覆盖 `terminal.write` / `session.open` 及新上传/下载 API 各自的专用单任务租约（下载见 §1.2）（见 [能力 API §2.1](07-capability-apis.md#21-独立上传任务sdk-211)），不是其它文件操作的通用授权；不能从 sudo 的专用宿主确认推出“所有能力经通用 Broker/完整进程隔离/审计均已实现”。本次实际边界见 §1.1。

## 1. 信任模型(分层陈述,禁止夸大)

| 资产 | v1 保护强度 | 依据 |
| --- | --- | --- |
| SSH 凭据(密码/私钥/passphrase) | **强**:物理上只存在于宿主进程与 OS 凭据库,无任何 RPC 可读取 | D5 |
| 会话通道(SFTP/exec/终端) | **强**:仅经宿主能力 API 可达,每次调用过 Broker,可撤销、有审计 | 06 |
| 宿主 UI 与其它插件 | **强**:进程隔离 + UI 全部宿主渲染;插件间无通道 | D1/D6 |
| 插件私有数据 | **中**:目录按插件划分 + secrets 命名空间隔离;同一 OS 用户下无强制隔离 | — |
| 本地文件系统 | **弱(v1)**:经 API 的访问受 Broker;但插件进程可直接 syscall 绕过 | 见 §3 |
| 网络出口 | **弱(v1)**:声明制 + SDK 审计;无物理拦截 | 见 §3 |

结论:v1 的安全承诺是"**插件拿不走你的凭据、碰不了你的服务器(除非
授权)、搞不垮你的主程序**";"恶意插件不能读你本地磁盘"在 v1 **不成
立**,靠来源信任(签名分档,见 10)把关。此表在用户文档与插件安装
确认页如实呈现。

### 1.1 此次 sudo 与 AI 托管执行的实际边界（SDK 2.1.0）

- 专用 `StreamSudoAsync` 只有目标、实际命令和非敏感选项；来源插件绑定宿主清单，目标取真实连接。宿主每次先确认**整条 root 命令（含管道/重定向）**，NOPASSWD/缓存有效也一样；插件审批的 Bypass 不能跳过宿主确认。密码输入不是命令授权。确认框可能在 Bridge/MCP 或免确认模式下异步弹出，所以「取消」是默认按钮并取得初始焦点，顺手的回车只能是拒绝；命令里的控制、格式、双向与零宽等不可见字符一律显示为 `⟨U+XXXX⟩` 并注明个数，多行或超过 400 字符的命令注明行数与长度，提醒滚动看完被推出可视区的末尾。交给登录 shell 的外层命令行编码为 `exec /bin/sh -c 'eval "$(printf %b "<payload>")"'`，payload 只含字母数字、少数标点与 `\0ooo` 转义，由 `/bin/sh` 自己还原；登录 shell 换成 fish（其单引号会把 `\\` 收成 `\`）或 tcsh 也改写不了已批准的命令。
- 密码只在宿主可信遮罩 UTF-8 输入框取得，不默认取 SSH 登录密码、不记忆；禁 CR/LF/NUL/控制字符，禁 undo，使用后清理可控缓冲与控件。受控 PTY 确认禁回显、匹配一次性提示且处在认证阶段才发送，最多三次密码应答、总认证等待两分钟；命令启动后应答入口不可逆关闭、stdin 关闭。无 UI/不支持的 PTY/PAM/OTP 明确失败，不在插件内询问、不绕 sudoers 限制、不重跑普通命令。用户命令的完整原始启动标记不能直接出现在 sudo 可回显的 argv 中，须由真正获准启动的 root 包装进程生成；策略拒绝的诊断回显不能制造 Running/Exited 或泄漏认证尾部。真实互操作曾发现并修复此客户端状态误判，不是 sudoers 授权绕过。随机标记不能防御已经被攻陷的远端。
- 密码与原始认证阶段内容不得进入插件/模型、RPC、历史、磁盘、日志、工具卡或 Bridge/MCP。连接级引用计数租约在敏感期间抑制**所有通道双向 payload**，保留必要元数据且不改用户诊断设置；要等对端 CLOSE 与发送泵排空或连接结束，不能以 Dispose 返回推断安全。开通道失败拿不到可跟踪通道时，保守抑制至连接结束。详见 [SSH 规格 §9.1](../ssh/spec/08-failures.md#91-敏感交互的连接级载荷抑制租约)。
- 托管任务绑定入口/对话/run、固定 sessionId；MCP 客户端隔离，查询/启动/完成重验 scope，清理取消不受读取授权撤销阻挡。完成通知时会话授权已撤销的后台任务只给模型一条「结果不予提供」的 Unknown 通知，不带输出、退出码或目标信息，本轮以 TaskUnknown 暂停。**现有撤权限制**：`ISessionScope` 没有 Changed/撤权事件且组成员查询有 5 秒缓存；MCP/Bridge 设置 reload 会取消旧 run，但普通会话树分组成员变更若未触发 reload，仅在上述检查点复验，不能承诺密码框期间即时撤权。
- 桌面/Bridge 中，插件审批拒绝/缺 Handler 与宿主 AuthenticationCancelled 都将当前 run 置为已拒绝，模型步骤、工具调用及后台续接强制 `ExecutionDenied` 暂停，不仅返回劝阻字符串；新用户轮次须新 run。对外 MCP 的拒绝只是那一次调用的结果：每客户端 host 仍用固定 scope，但不因拒绝封住，后续工具照常可用，停不停由 MCP 客户端决定。后台完成通知把远端输出整体框为不可信数据：包进 `<untrusted-command-output>`、声明是命令输出而非用户指令，内容经 JSON 转义、伪造不出结束标记；这是提示注入的缓解，不能保证模型不被输出里的文字诱导，边界仍是插件审批与宿主确认。Stop/入口销毁/卸载与隔离连接断开会取消并异步收尾；取消请求不保证远端已停止。Unknown、缺失退出码、已启动超时且未确认停止禁止自动推进/副作用重放。此功能不是用户终端自动填充，不修改已有终端凭据交互决定，也不支持 su/任意 stdin 或跨重启恢复。

SDK 2.1.0 已正式发布并用于宿主/AI，执行 RPC、Capability 及 sudo 参数化回归已通过；Ubuntu/Debian 的真实 sshd/PTY/PAM 执行内核矩阵（含重试、取消、策略拒绝）已通过。宿主 sudo 对话框及相关本地化/调度/样式门禁已通过（不是全 UI 套件），最新拒绝守卫后的全 AI 与 SSH 定向回归已通过，最终 Debug 严格非增量构建与风格收尾后的重新编译定向回归也已通过；真实内核不等于 GUI 与插件 IPC 整链真实验收，认证超时/迟到租约综合动态范围不能自行扩大。当前发布/验证边界见 [自动化与 AI §1.4](11-automation-and-ai.md#14-ai-插件的托管执行与恢复sdk-210)。

### 1.2 后台下载的实际安全边界（SDK 2.1.2）

- 新下载的 `DownloadPermissionLease` 与上传租约分开，逐任务确认插件、真实会话、远端源、最终本地目标和覆盖策略，检查远端读/本地写。默认不覆盖，明确覆盖须批准；AI Bypass、保存选择器、终端或开会话许可都不能代替宿主确认，无 UI/提示器则拒绝。撤权取消待批准及活动租约，提交前重验，后续结果脱敏；清理取消仍允许，不承诺已提交文件回滚。这里不是通用文件 Broker 或对同用户恶意插件 syscall 的物理隔离。
- 安全提交覆盖 Windows 固定本地 NTFS 与 Linux / macOS（x64、arm64）的本地文件系统：审批前钉住整条目标目录链，之后建临时文件、提交与清理都相对钉住的父目录，祖先事后被改名或换掉也落不到别处。Windows 逐段持有带遍历权限的祖先目录句柄（只读属性的句柄不参与共享检查），共享读写、不共享删除，祖先改不了名、挪不走；只有名字代理类重解析点（符号链接、目录联接、挂载点）算链接并拒绝，OneDrive 云文件占位符等过滤器标记不算，标记读不出按链接算；临时文件按句柄核验建在钉住的父目录里，提交经 `NtSetInformationFile` 相对父目录句柄、只给末级名字。Linux / macOS 先把父目录解析成真实路径（审批框显示的就是它），再从 `/` 起逐级 `openat(O_DIRECTORY | O_NOFOLLOW)`、只留父目录 fd，链上任何一级是符号链接即拒绝；按路径寻址的文件系统上目录 fd 钉不住改名（WSL 的 `/mnt/c` 即 9p 上实测），所以只收本地、按 inode 寻址的文件系统，9p / SMB / FUSE / NFS 在审批前拒绝。临时文件独占新建（POSIX 为 `O_EXCL | O_NOFOLLOW`，用着时一直持有 flock）；默认原子无替换（POSIX 用 `renameat2(RENAME_NOREPLACE)` / `renameatx_np(RENAME_EXCL)`，标志不被支持时 `linkat` 兜底，两条都走不通按不支持拒绝），目标中途出现也受保护；明确覆盖不先删目标，POSIX 上新文件沿用旧文件的权限位、不带 setuid / setgid / sticky。崩溃遗留的 `.vela-download-*` 在下次打开同一目录时清扫：名字逐字对得上、且能以可删除不共享方式打开（Windows）或拿得到 flock（POSIX）的才删，在写的不动，同形链接只删链接本身。时间戳设置作用于持有的临时句柄，用户最终路径不交旧同步下载。UNC、其它文件系统/后端明确拒绝，不以字符串前缀预检冒充抗竞态，也不退回直接写最终路径。
- 校验实际长度、传输前后远端元数据及可用摘要；纯 SFTP 不强制 exec/默认二次整文件下载，检测源变化则失败，但不保证远端原子快照。进度满字节不是成功，只有校验、关闭、安全提交确认后才 Succeeded。取消不等于停止，后端不合作时先 Unknown/TimedOut且停止未确认，保留槽/句柄直至实际退出；不自动重下或声称已回滚。
- 两入口移除的是32/64 MiB AI固定大小判断，不是授权、下载限速、磁盘、共享任务额度、模型上下文或IM附件边界。模型Stop不取消任务；显式取消、面板关闭/入口销毁、插件停用及授权重载走清理。任务按owner/run隔离，模型终态消费一次，MCP主动查询；路径/错误按不可信数据处理。`send_file`不能在下载提交前消费目标或同名旧文件，外发审批与平台限制保留。
- 下载契约已随 SDK 2.1.2 正式发布，宿主中央包、AI 显式依赖与 minSdk 均为 2.1.2，不使用本地包。安全落盘的提交用例在 Windows 与 Linux 上实际跑过，macOS 只经 CI；不宣称真实 SSH / GUI 整链已通过。详细行为与发布状态见 [自动化与 AI §1.7](11-automation-and-ai.md#17-ai-双入口后台下载sdk-212)。

### 1.3 只读 Subagent 与外部 MCP 的实际边界

- 子 Agent 继承父轮的本地工作区与 SSH 会话范围，默认只读；每次委派可显式 `allowWrites=true` 开放现有本地/远端文件修改工具，仍受禁用项、父轮实时审批及拒绝停止边界约束，不提供进程启动、终端、传输、会话创建、审批管理或再次委派能力。父子内置文件修改共用可取消的串行锁，防止同工具箱内补丁读改写交错，不协调其它聊天、外部程序或 MCP，不提供事务或回滚保证。MCP 只读声明是工具筛选依据，不证明服务器实现没有副作用；继承的 MCP 工具仍经过审批包装。
- 独立模型选择不扩大工具范围；候选与执行均限制为当前供应商实例下的已配置聊天模型，以实例 ID 而非名称匹配，拒绝图片模型和其他供应商。桌面按当前父模型（含故障转移）限定，IM 按本轮父模型限定；对外 MCP 在连接建立时固定供应商。复用父模型时复验父凭据，其它模型使用自己的凭据解析与配置校验；同供应商模型仍可配置独立端点和密钥，因此配置归属不等于相同网络接收方。无效模型或凭据变化明确失败，不借用父模型密钥，也不在任务结果中记录密钥。
- 桌面对话作图使用独立开关及可选默认值。自动候选仅当前供应商图片模型，但用户明确配置的默认图片模型可以来自另一供应商，工具描述与审批显示目标。模型只能传候选配置 ID，不能传地址或密钥；执行前和审批后复核开关、默认值及目标快照。失败不自动重试或换服务，回执标识请求的模型配置，不能证明上游实际使用的模型。
- 对外 MCP 在 Agent 模式且已配置聊天模型时向外部 agent 暴露 `delegate_subagent`：外部 agent 因此可以让 VelaShell 用用户配置的模型发起请求，消耗用户的模型额度，并把子任务在该连接范围内读到的文件、终端输出与网页内容发送给该模型的供应商。子任务的工具范围与挡位与该连接相同，不扩大可读写的范围；没有审批界面，写入仅在绕过审批挡位下可行；每条连接最多 32 个子任务、并行 4 个。该能力默认随 Agent 模式开启，可在对外 MCP 的工具配置里停用 `delegate_subagent`。IM 桥接的子任务沿用该聊天的授权与审批，审批消息标明来源子任务。
- MCP 停止会取消连接 lifetime，使旧工具与待审批调用失效。`KeepAlive=false` 在最后一个轮次租约释放后断开连接，避免并发聊天互相断开；取消请求和客户端断开不保证远端服务器已停止执行或副作用已回滚。
- Stdio 默认 Minimal 仅传递 SDK 必要环境集合，None 仅使用显式变量，All 继承宿主环境；显式配置会覆盖继承值。这减少意外传递环境秘密，但不会隔离服务器进程的文件系统、网络或同用户权限。工作区绑定只设置获授权的工作目录，不是进程沙箱。
- 运行卡片记录实际委派、工具计数和错误，不能证明模型总结正确。当前自动化覆盖本地协议与 UI，不代表真实供应商必然委派或各平台 Stdio 子进程退出均已验证。操作说明见 [自动化与 AI](11-automation-and-ai.md)。
- 已在 Windows 用真实 Stdio 测试进程验证环境继承、工作目录和停止/重启/停用/租约释放/启动超时后的进程退出；这不等于任意服务器及 Linux/macOS 已验收，也不能由客户端退出推断远端操作已回滚。

## 3. OS 级沙箱路线(v2+,预研项)

目标:把 §1 的两个"弱"升为"中/强",让 fs.local/network 权限获得物理
强制。按平台可行性排序:

| 平台 | 手段 | 预判 |
| --- | --- | --- |
| Linux | Landlock(文件范围)+ seccomp(syscall 面收敛)+ cgroups v2(资源) | 最可行,内核 ≥5.13 |
| macOS | `sandbox_init` profile(Apple 半私有但 Chromium 等在用)或 App Sandbox 化的 helper | 可行,需打磨 |
| Windows | Restricted token + Job Object 起步;AppContainer 为终态(管道 ACL 需配套放行) | 工作量最大 |

原则:沙箱是**能力收敛器**而非权限系统替代——Broker/授权 UX 不变,
沙箱把"合规契约"变成"物理不可为"。路线图上 M8 启动预研,先 Linux。
