## 0. 结论先说

- 主密码是**可选**的第二层，默认关。开了之后，系统密钥链（macOS 钥匙串 / Secret Service）或 Windows DPAPI 文件里存的不再是本机加密密钥本身，
  而是**用主密码派生的密钥包裹过的本机密钥**：密钥链条目和主密码两样都在才解得开。
- **已存的 `enc1:` 密文一字不改**。主密码包的是本机密钥（数据加密密钥，DEK），不是每条密文 —— 开启、关闭、修改主密码都只重写几十字节的包裹，
  秒级完成，不碰数据库。这也是 KeePass / Bitwarden / 1Password 的做法。
- 解锁：主窗口出现后弹一次解锁框（可取消）；取消或锁定期间应用照常可用，只是已存的密码读不出来，状态栏左侧留一个锁形入口随时再解锁。
  自动重连、睡眠唤醒后的批量重连、隧道自动重建、Gist 自动同步按「锁着」处理，**不弹框**；插件读写机密这一轮先**等交互式解锁**（§6）。
- **忘记主密码 = 已存的机密作废，没有后门**。开启时默认生成一份恢复码（可跳过），它也能解开；两样都没有时「忘了主密码？」另起新密钥，
  旧的包裹、头文件与数据库里的旧密文都保留不删（想起来还能解）。

## 1. 第一步之后的现状

- `MasterKeyResolver` 解析出一个**密钥环**（一把或几把 32 字节 DEK，第一把用来加密，解密依次试）；macOS / Linux 上每把一条密钥链条目
  （编号 = 域分隔 SHA-256(DEK) 前 128 位），数据目录 `secret.key.ref` 只列编号；Windows 上是 DPAPI 包裹的 `secret.key`；密钥链用不了时回落到明文 `secret.key`。
- `ISecretProtector` 是同步的 `string → string`，调用方遍布会话仓储、共享凭据、Gist、插件机密、插件信任库；`TryUnprotect` 能如实说「解不开」。

## 2. 威胁模型：主密码多挡住什么

| 场景 | 第一步（密钥链） | 加主密码 |
| --- | --- | --- |
| 拷走 / 备份 / 网盘同步数据目录 | 挡住 | 挡住 |
| 同一用户下的其它程序读密钥链条目（macOS 条目对任何应用开放；Secret Service 解锁后对会话内进程开放；DPAPI 对本用户进程开放） | **挡不住**（与原来 0600 文件同级） | 挡住（还要主密码） |
| 钥匙串 / keyring 文件连同登录密码一起泄露、域管理员重置账户后的 DPAPI | 挡不住 | 挡住 |
| 别人坐到你已登录、没锁屏的电脑前打开 VelaShell | 挡不住 | 锁定期间挡住（§5 自动锁定） |
| 解锁之后读进程内存、键盘记录 | 挡不住 | **挡不住**（如实写，不承诺） |
| 进程内插件（与宿主同进程） | 挡不住 | 解锁后挡不住；隔离插件仍只经 `ISecretsApi` 拿到自己的机密 |

## 3. 密钥层次与存储格式

```
主密码 ──Argon2id(salt, m, t, p)──► KEK（32 字节，只活到包裹 / 解包完成就清零）
恢复码（128 位随机）──HKDF-SHA256(recovery-salt)──► RK（同上）
                                     │ AES-256-GCM（随机 12 字节 nonce，附加认证数据 = VSMP1 ‖ 种类 ‖ 包裹编号）
DEK（第一步密钥环里的每一把） ────────►  记录 = 种类 ‖ 包裹编号 ‖ nonce ‖ tag ‖ GCM(KEK 或 RK, DEK)
```

- **KDF 头**（盐与参数，不是机密）存在数据目录的 `secret.key.mp`：`version=1`、`kdf=argon2id`、`m`、`t`、`p`、`salt`（16 字节随机，base64）、
  `recovery-salt`（生成了恢复码时才有）、`state`（`active` / `enabling` / `disabling`，见 §7）。参数超出合理范围（m 大于 1 GiB、t 大于 64、p 大于 16）一律当成读不出来 ——
  免得一份被改大的头拖死解锁。整个密钥环共用一个 KEK（一次派生解开全部）。
- **包裹**（每条密钥链条目、或密钥文件的内容）从「32 字节 DEK」换成 `VSMP1` 魔数 ‖ 一条或几条**记录**；每条 69 字节：
  种类（1 字节，`P` = 主密码、`R` = 恢复码）‖ 包裹编号（8 字节，= 域分隔 SHA-256(种类 ‖ 对应的盐) 前 64 位）‖ nonce（12）‖ tag（16）‖ 密文（32）。
  一般是两条（主密码一条、恢复码一条；跳过了恢复码就一条）。修改主密码的过渡期里会短暂多一条（§7）；编号对不上当前头的记录是过渡的残留，解锁时不用、成功解锁后清掉。
- 条目编号仍按 DEK 派生，不变 —— 所以第一步「条目内容对不上编号就不用也不动」的规则天然保护了包裹过的条目：不认 `VSMP1` 的旧版本读到它只会报「找不到」、另起新密钥，不会覆盖。
  解开之后同样对着编号自证：解得开、却不是这个条目名下的那把（条目被人换过）就不用。
- **Windows**：`secret.key` 的内容从 `DPAPI(DEK)` 换成 `DPAPI(VSMP1 ‖ 记录)`；回落到明文文件的平台同理（`VSMP1 ‖ 记录`，这时主密码是唯一屏障）。替换密钥文件一律先写临时文件、落盘、再改名覆盖。
- 校验：GCM 认证标签即主密码校验，不另存验证值（少一个可供离线比对的东西）。恢复码是 128 位随机数（外加 1 字节校验，写成 28 个 Crockford base32 字符、每 4 个一组），
  不怕离线穷举，所以派生用 HKDF 而不是 Argon2id；校验字节只用来把抄错一位说成「恢复码写错了」，不计一次输错。
- **事实来源是包裹格式本身**，不是 `AppSettings.MasterPasswordProtection`：设置导入、Gist 同步都可能改那个布尔值。
  字段只是给界面看的镜像（设置页按实际状态回写），登记在 `SettingsCategories.StateFields`（导出不写、导入保留本机的、审计不算），云同步推送前清掉、拉取时保留本机的。
- **怎么判定「开着」**（解析时）：找到了包裹 → 开着；头在、包裹一个没找到，但有条目这次没问成（密钥链用不了）→ 当成开着、锁着、说不清能不能解（`KeysUnavailable`）；
  头在、包裹一个没有、每个位置都问到了 → 头是 `enabling` / `disabling` 时删掉它（开启连一把都没包就断了 / 关闭已经全写回明文），是 `active` 时改名保留成 `secret.key.mp.orphaned-时间戳`、按没开继续并在消息中心说明；
  有包裹却没有头（`HeaderMissing`）或头读不出来（`HeaderUnreadable`，原样留着）→ 开着、解不了锁，只能「忘了主密码？」。
- 开着时解析**不生成、不迁移任何密钥**：另起一把主密码管不到的新密钥，等于悄悄把保护关掉。密钥链暂时用不了时第一步会另起一把本地临时密钥，开着时不许。
- 备选方案（不采用）：开主密码后把密钥只存成数据目录里的包裹文件、删掉密钥链条目 —— 数据目录 + 主密码即可换机，
  但主密码弱时等于退回「拿到目录就能离线爆破」，与第一步的目的相反；换机已有连接导出与端到端同步。

## 4. KDF：Argon2id

- 参数：m = 64 MiB、t = 3、p = 1（RFC 9106 §4 的第二推荐是 m = 64 MiB、t = 3、p = 4；OWASP 的下限是 m = 19 MiB、t = 2、p = 1），主流笔记本上约 0.3–0.6 秒。
  维护者 2026-10-31 定：不为低端机降参。参数随头存；头里的参数不是出厂参数时，下一次用主密码解锁成功就用新参数、新盐重新包裹（rehash，走 §7「修改」的三步），不需要一次性迁移。
- 实现：BCL 没有 Argon2。宿主经 `VelaShell.Ssh` 已带着 BouncyCastle.Cryptography（`.ppk` v3 的 Argon2id 用它），Infrastructure 显式引用同一个包，不新增依赖；
  `src/Directory.Packages.props` 的注释里登记了这项新用途（`VelaShell.Ssh/README.md`「没有第二种用途」说的是 SSH 库内部）。
- 派生放线程池（64 MiB 内存、几百毫秒 CPU），对话框显示忙碌态、按钮变灰；派生一旦开始就做完，等待被取消也不半途撂下。
- 在线防猜：连续输错第 n 次之后要等 2^(n-1) 秒（1、2、4… 上限 30 秒）才能再试，对话框倒数；不锁死、不删任何东西，计数只活在这个进程里。
  离线防猜只靠参数与密码强度：新主密码短于 12 个字符时提示「至少 12 个字符或一句口令短语」，只提示、不拦。口令框是 `SecurePasswordBox`，只收可打印的英文字符（与其它密码框一致）。

## 5. 解锁、锁定态与保存

- **何时解锁**（维护者 2026-10-31 定）：主窗口出现后弹一次解锁框，可取消；取消后状态栏左侧留一个锁形入口（锁着时点它解锁，解着时点它立即锁定）。
  启动时恢复的那几个会话同时在等解锁，与这个框共用同一个。
- **锁着时的语义**：`AesSecretProtector` 没有可用的密钥串 → `TryUnprotect` 为 false、`Unprotect` 原样交回密文（与第一步「密钥没取到」完全同一条路，调用方已经会处理）；
  `Protect` 对新的明文抛 `SecretsLockedException`（对已经是密文的值照旧原样交回，幂等）；`ISecretProtector.IsLocked` 如实说。
- **仓储锁着时把机密字段冻在库里那一份上**：会话配置的密码 / 私钥口令 / 插件机密、共享凭据的密码 / 口令、设置里的代理密码 —— 传进来的已经是密文就照存，
  否则一律取库里现存的那份（没有就是空），别的字段照常保存。新的明文存不进去，旧的也不会被一份空值（「记住密码」没勾的副本、解锁取消后剥掉机密的副本）
  或锁定前解开、还在内存里的明文顶掉。旧 `sessions.json` 的一次性导入锁着时推迟到解锁之后。
- **异步闸口** `IMasterPasswordGate { bool IsEnabled; bool IsLocked; Task<bool> EnsureUnlockedAsync(bool interactive, CancellationToken); event Unlocked; event Locked; }`，
  管理入口 `IMasterPasswordService`（解锁、恢复码解锁、立即锁定、开启 / 关闭 / 修改 / 忘记、状态）。并发的交互式请求共用同一个框的结果，用户取消后排着的一起拿到 false，不再逐个弹；
  界面层注册 `IMasterPasswordPrompt`（模态于此刻活动的窗口），容器里取不到时（headless、测试）交互式请求也只能是 false。
- **用到机密的入口先过闸**：连接的构建点（主动连接、打开 SFTP / FTP / 插件文档与插件终端、隧道面板后台连接）都在既有构建点前插一层：
  这条连接会用到已存机密（存着密码 / 口令 / 插件机密、引用共享凭据、经跳板）而又锁着时先弹框；解开了就把锁着时载入的密文换成库里现在解得开的明文；
  取消了，**锁定前留在内存里的明文也不拿去用** —— 剥掉这一份的已存机密，登录框问这一次的密码，连上后存回去时仓储照旧不动库里那份。
  编辑一条存着机密的连接、保存共享凭据、导入连接(Xshell / WinSCP / OpenSSH / 连接文件)、存 Gist 令牌 / 口令、手动同步同样先弹框；取消就照存别的字段，并明说「未解锁，这次的密码没有保存」。
- **自动锁定**（维护者 2026-10-31 定：默认不自动锁，可选）：「空闲后自动锁定（分钟）」只看本应用窗口里的键盘、鼠标、滚轮、触摸（全部顶层窗口上挂的隧道类处理器），
  终端里一直在刷的输出不算操作；「系统锁屏时锁定」目前只在 Windows 上读得到（`WTSQuerySessionInformation` 的 `SessionFlags`，读不到就不锁），
  macOS / Linux 暂无读法，设置页不显示这一项（免得开了却不起作用）。检查在线程池定时器上每 5 秒一次；解锁的那一刻空闲计时清零。
- **锁定 = 清零内存里的 DEK**（`CryptographicOperations.ZeroMemory`）回到锁着；加解密都在同一把锁里做，锁定不会与一次正在进行的加密交错。
  之后会话树重读（锁着时仓储交回的是密文），手动重连与新开连接都要先解锁。**不清的**：已经连着的会话、已经开着的 FTP 连接池照常工作；
  代理密码仍在内存里（否则所有走代理的连接都会断）；已开标签里那份配置的内存副本不清，但锁着时拿它重连、克隆都要先过闸。
- **解锁框**：模态于此刻活动的窗口，`SecurePasswordBox`，不进剪贴板、不进历史；可切到「用恢复码解锁」；头不在 / 读不出 / 密钥链没打开时直接写明原因，只能取消或「忘了主密码？」。

## 6. 自动重连与后台任务

与[凭据管理器集成设计](凭据管理器集成设计.md) §5.7 同一张表（那里的「保险库锁定」即这里的「主密码锁定」）：

| 触发 | 模式 | 锁着时 |
| --- | --- | --- |
| 用户主动连接、手动重连（Ctrl+R / 回车 / 「重连」）、打开 SFTP / FTP / 插件文档、插件 `Sessions.OpenAsync`、启动时恢复会话、隧道手动启动 | 交互式 | 弹解锁框（同一时刻只有一个） |
| 自动重连定时器、睡眠唤醒后的 `ReconnectAllAfterResume` | 非交互式 | 不弹框；标签失败覆盖层写「已锁定：自动重连不会弹出解锁框。解锁后会自动重试一次，也可以按回车或 Ctrl+R 重连」；解锁成功后对这些挂起的标签各重试一次 |
| 隧道 `AutoReconnectAsync` | 非交互式 | 不弹框、不进退避；面板说明解锁后自动重建；解锁后各重试一次 |
| Gist 自动同步 | 非交互式 | 跳过这一轮并记一行（`[Sync] Skipped: saved secrets are locked…`）；手动「立即同步」先弹框 |
| 插件读写机密（`ISecretsApi.GetAsync` / `SetAsync`） | 交互式（维护者 2026-10-31 定） | 先等交互式解锁（弹框，或等着已开着的那个）；取消则抛 `PluginPermissionDeniedException`（SDK 现有能表达的最接近语义 ——「用户没让读」，线上码 `permission-denied`，隔离插件经 RPC 照样还原）。**绝不返回 null**：插件会以为机密不存在、让用户重填，覆盖旧值。删除不用解密，照常放行 |
| 连接诊断 | — | 这一轮没接闸口：锁着时第 4 步拿到的是解不开的密文，按「已存的密码解不开」标成要人补（与第一步同一口径） |
| 插件信任库 | — | 启动时不等：发现与应用自带插件照常；装在用户目录的插件要校验收据，校验那一步等到解锁后才做（不弹框）。管理页查询不等、写明「锁着」而不是「无法读取」（那条提示会劝人去重置）；安装插件、信任发布者先弹框 |

理由同凭据管理器设计：网络恢复后 20 个标签同时自动重连，不能弹出一个用户不知由谁触发的解锁框（钓鱼疑虑）。

SDK 里另写好了「已锁定」契约（velashell-plugin-sdk 分支 `feat/secrets-locked`，可用版本 TBD）：`SecretsLockedException`（继承 `InvalidOperationException`）、
`ISecretsApi.SupportsLockedState`（默认 false）、`HandshakeResponse.SupportsSecretsLocked`、线上码 `secrets-locked`、`FakeSecrets.IsLocked`。宣告了能力位的宿主锁着时读 / 写不弹框、直接抛它；
**宿主这一轮不接**，发版后再决定后台读机密改不改成非交互式。

## 7. 开启 / 关闭 / 修改 / 忘记

每一步都只动包裹，不动密文；每个位置都是「写新、读回逐字节核对」才算数；有位置这会儿问不到（系统密钥链用不了）时一律不动手 ——
那个位置是什么样子不知道，动了别的就可能留下一把再也解不开的。

- **开启**（设置 → 常规 → 隐私与安全，恢复 R-04 那一行）：输入两次、强度提示、勾「我明白：忘了主密码（又没有恢复码）时，已保存的密码无法找回」、默认勾「同时生成恢复码」→
  现读一遍每个位置（清单里的每个条目 + 本地密钥文件；内存里用着的每一把都得在某个位置上，否则拒绝）→ 先写一份 `state=enabling` 的头 → 派生 KEK（与 RK）→
  逐个位置写包裹并核对 → 头改成 `active`。任一位置写不进：已经包上的写回明文、删头，整体回到没开；回滚也写不进时如实交代「主密码现在是开着的，用刚输入的那个解锁」
  （头留在 `enabling`，下次解锁时把还是明文的那几个也包上）。恢复码只在这一步显示一次。
- **关闭**：输入当前主密码 → 解开每一份包裹（每一份都得解得开）→ 头标成 `disabling` → 逐个写回明文 DEK（第一步形态）→ 删头。中途失败写回原包裹、头改回 `active`；
  断电断在写回之后，下次启动（包裹全没了、头是 `disabling`）就删头收尾，断在写回一半，下次用主密码解锁时接着关完。
- **修改**：旧 + 新 → 解开每一份 → 新头（新盐、出厂参数、恢复码的盐沿用）→ ①每个位置**加上**新主密码那一条（旧的那条、恢复码那条都留着）→ ②原子换头 → ③删掉旧的那条。
  断在①之后旧主密码照样解得开（新记录对不上当前头，下次解锁时清掉）；断在②之后新主密码解得开；③没做完只是多一条用不上的记录。①② 失败都写回原样的字节、头不动。恢复码不受影响。
- **用恢复码解开之后**：要求设一个新的主密码（可以「以后再说」，下次启动仍可用恢复码），做法同「修改」，恢复码照样有效。恢复码解不开的那一份（降级回来后才包上、没有恢复码记录的）这一步包不了，
  旧头另存一份 `secret.key.mp.superseded-时间戳`，想起旧主密码还有得救。
- **忘记**：解锁框上「忘了主密码？」→ 说明后果 → 确认「另起新密钥」：头、清单、密钥文件改名保留（`.forgotten-时间戳`，不删；密钥链里的旧条目原样不动），
  另起新的本机加密密钥，主密码随之关掉。之后与第一步「条目找不到」同一条提示路径：连接时重新输入；插件信任库同样解不开，要在插件管理页重置。
  想起来了，把那几个文件改回原名即可（自动化用例覆盖了这条路）。
- **审计**：开启 / 关闭 / 修改（含恢复后设新密码）/ 忘记各记一条 `settings` 类审计（`master-password-enabled` / `-disabled` / `-changed` / `-reset`），只记动作（开启时记有没有恢复码、忘记时记保留的文件名），不记任何口令材料。

## 8. 迁移与兼容

- 第一步 → 第二步：只在用户开启时一次性包裹；不开的人什么都不变（解析、迁移、回落与第一步逐字节一致）。
- 降级到不认 `VSMP1` 的版本：
  - **macOS / Linux**：包裹过的条目对不上编号 → 旧版本报「找不到」、另起新密钥、不覆盖；旧版本里已存密码解不开。升回来时那把明文存着的新密钥锁着时不用，用主密码解锁后包上并入，新旧密码都解得开。
  - **Windows**（以及没有密钥链、只有密钥文件的情形）：旧版本读到 `DPAPI(VSMP1 ‖ 记录)` 只当「密钥文件用不了」，原样改名保留成 `secret.key.unreadable-时间戳` 再另起新密钥（不覆盖）。
    升回来时头找不到它包裹的任何密钥 → 改名保留成 `secret.key.mp.orphaned-时间戳`、按没开继续、消息中心说明；降级之前存的密码需要重新输入。
    〔已知限制〕不自动从 `.unreadable-*` 里把包裹过的那把找回来：Windows 上只有一个密钥文件位置，放不下两把；文件都在，手工改回原名（并删掉旧版本新生成的 `secret.key`）可以恢复。
- 多设备：主密码只管本机；云同步的端到端口令是另一回事，不合并、不复用（避免一个口令泄露两处都失守）。

## 9. 决策（维护者 2026-10-31 定）

1. 解锁时机：主窗口出现后弹一次解锁框，可取消；取消后状态栏留一个锁形入口，点它再解锁。
2. 自动锁定：默认不自动锁；提供可选「空闲 N 分钟后锁定」「系统锁屏时锁定」，设置项当场接线（系统锁屏目前只在 Windows 上读得到，别的平台不显示这一项）。
3. 恢复码：开启时生成一串 128 位随机恢复码（可跳过），它也能解包 DEK（多一份包裹）。
4. 插件 `ISecretsApi` 锁着时：宿主先按「等待交互式解锁」处理，取消按 SDK 现有能表达的最接近语义（`PluginPermissionDeniedException`），绝不返回 null；
   同时在 SDK 里另写「已锁定」契约（§6 末），宿主这一轮不接。
5. Windows Hello / Touch ID 作为解锁方式（[调研](系统密钥链与sudo凭据填充可行性调研.md) §8 第 2 条）：留到第三步，不做。
6. Argon2id 固定 m = 64 MiB、t = 3、p = 1，不为低端机降参；参数随头存，以后调参靠 rehash。

## 10. 测试

均在 Windows 上实跑；macOS 钥匙串 / Linux Secret Service 的真机路径只经 CI 编译与假密钥链用例（`VELASHELL_KEYCHAIN_TESTS=1` 的真密钥链往返没跑）。

- `MasterPasswordFormatTests`：头、包裹、恢复码的往返与拒收（参数越界、截断、重复键、记录挪到别的种类）；锁着时 `Protect` 不生新密钥、`TryUnprotect` 为 false、
  密钥链用不了时不另起临时密钥；解锁、输错的 1 / 2 / 4 … 30 秒退避、恢复码（抄错不计次）、锁定清零；条目解开却对不上编号不用；开启 / 关闭断在中途的收尾；
  降级 —— 用第一步原样拷贝的旧解析器（测试夹具）读包裹过的条目：不覆盖、另起新密钥，升回来解锁后新旧都解得开；Windows 那条的头改名保留。
- `MasterPasswordOperationsTests`：开启 / 关闭 / 修改在写到一半失败、回滚也失败、密钥链用不了时都不丢任何一把 DEK；修改断在加记录之后 / 换头之后两处都有口令解得开、残留记录被清；
  恢复码解开后设新主密码、恢复码仍有效；忘记后的改名保留与改回原名找回；旧参数的头解锁后 rehash；设置导入手写 `masterPasswordProtection: true` 不改本机、也不影响实际状态；审计各一条、不含口令。
- `MasterPasswordLockedStateTests`：非交互式不弹框、十个并发交互式请求只弹一个框、取消后一起拿到 false；仓储冻结（会话配置、共享凭据、代理密码 —— 含锁定前解开过的那份不被抹掉、解锁后就地填回）；
  Gist 锁着时跳过这一轮而不是报「请重新填写令牌」；插件机密锁着时绝不交回 null、删除照常。
- 宿主：`MasterPasswordConnectFlowTests`（自动重连锁着时不弹框、说明原因、解锁后只重试一次；手动重连弹框；取消后不用内存里的明文；用不到已存机密的连接不过闸）、
  `MasterPasswordAutoLockTests`（默认不锁、空闲计时与解锁清零、系统锁屏读不到就不锁、Windows 上读得到本会话「没锁」）、`MasterPasswordDialogUiTests`（对话框各样子与 headless 外壳规格）、
  `NotificationSourcesTests` 新增两条。
