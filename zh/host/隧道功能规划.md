# 隧道功能规划（Plan）

> 更新于 2026-08-30。原"待实现"1~4 项与后续三项迭代（断线自动恢复 / 流量统计 / 端口冲突预检）均已落地；剩余想法见文末。

## 已实现

- 本地转发（-L）、远程转发（-R）、**动态转发（-D / SOCKS5）**三种类型，创建时下拉选择（动态转发自动隐藏目标主机/端口输入）
- 远程主机从资源管理器已保存的 SSH 会话中选择（服务端口手动填写）
- 隧道行内操作：停止 / 启动 / 删除（删除活动隧道时先自动停止）
- 表单"取消"清空重置；创建失败错误内联显示
- **隧道配置持久化**：按服务器分文档存入 SonnetDB `tunnels` 集合（docId = profileId，经 `IAppDataStore`）；应用重启后恢复为"已停止"状态，可一键启动（每次运行每台服务器只恢复一次，恢复失败不影响面板）
- **独立承载会话**：隧道生命周期独立于终端标签——未连接时创建/启动隧道会自动建立仅隧道用途的后台连接；该服务器最后一条隧道删除后后台连接自动断开
- **多端同步**：隧道配置随「连接配置」范围纳入 Gist 云同步（plan.md §13.C）

### 计量转发（自建数据面，2026-08-30）

底层库 Tmds.Ssh 把端口转发的搬运整个做在内部，**不暴露任何连接数或字节计数**，
`TunnelInfo.BytesTransferred` 因此长期恒为 0。要出统计只能自己接管数据面，于是
`Infrastructure/Ssh/MeteredPortForwardHandle` 取代了原先直接返回库对象的做法：

| 类型 | 监听端 | 出站 | 备注 |
| --- | --- | --- | --- |
| 本地转发 | 宿主自己的 `TcpListener` | `SshClient.OpenTcpConnectionAsync`（direct-tcpip） | 与库内部同构，无额外跳数 |
| 动态转发 | 宿主自己的 `TcpListener` | SOCKS5 握手协商出目标后同上 | 服务端握手见 `Infrastructure/Ssh/Socks5Negotiation`（RFC 1928，仅 CONNECT + 无认证） |
| 远程转发 | 服务器侧，仍由库开 | 库转发到本机临时计量监听 → 宿主接力到真实本地目标 | 多一次环回拷贝换来同样的统计 |

三条路径收敛到同一个"监听 → 建出站流 → 双向搬运"的循环，沿途累加字节数与连接数。
搬运保留**半关闭语义**（一个方向读到 EOF 就向对端发 EOF：SSH 侧用 `SshDataStream.WriteEof`，
套接字侧用 `Shutdown(Send)`），否则"发完请求就 shutdown 再等响应"的协议会读不到东西。

### 流量统计（2026-08-30）

- 每条隧道的行内显示 `3 连接 · 1.4 MB`；有正在传输的连接时并发数一并点出（`3 连接（2 在传）· 1.4 MB`）
- 字节数为**上行 + 下行**合计，只统计真正流过转发的业务数据，不含 SSH 协议开销与 SOCKS 握手字节
- 读数由 `ITunnelService.RefreshStatistics()` 从底层句柄同步到 `TunnelInfo`，面板的 5 秒状态时钟调用；
  隧道停止时先取下最后一次读数再释放句柄，因此"已停止"的隧道仍显示它跑过的总量
- 设计稿 fuXS7 预留的说明行即此行

### 断线自动恢复（2026-08-30）

- 新建/编辑表单里的「掉线后自动重连」开关，落到 `TunnelConfig.AutoReconnect`（随配置持久化与云同步；
  旧配置缺该字段时按 `false` 反序列化）。勾选的隧道在列表里带一枚 `自动` 徽标
- **默认关闭**：自动重拨可能触发凭据提示，也可能对着一台真的下线了的服务器反复重试，该由用户按隧道自己决定
- 面板的状态时钟检出后台会话掉线后，为勾选的隧道重拨承载会话并按原配置重建转发；
  掉线检测覆盖**面板持有的每一台**服务器，而不只是当前选中的那台
- 失败按 10s → 30s → 1min → 2min → 5min 退避，避免服务器真的下线时每 5 秒重连一次
- **用户按停过的隧道不会被自动拉起**：`TunnelItemViewModel.StoppedByUser` 记下"这是用户按的停止键"，
  自动恢复放过它。重建出来的是新条目，自然回到可恢复状态

### 端口冲突预检（2026-08-30）

- 创建本地转发/动态转发前比对系统 TCP 监听表，命中即抛 `TunnelPortInUseException`，
  提示"本地端口 27017 已被其它程序占用"，而不是底层套接字那句只有写网络代码的人看得懂的错误
- 判定规则：端口号相同，且任一方绑在"所有接口"上、或两者监听地址相同（不同网卡的同一端口可以并存）
- 远程转发的监听在服务器上，不做本机预检
- 预检与真正的绑定之间的竞态是已知且可接受的：预检负责把最常见的情形讲清楚，真绑不上时底层异常仍会照常抛出
- 探测委托可注入（`TunnelService` 构造的 `isLocalPortInUse` 参数），否则单元测试的结论就要看运行机器上
  恰好有没有数据库在监听 5432

## 后续想法

1. **按方向拆分流量**：目前 `BytesTransferred` 是上下行合计，分开显示能更快看出是上传还是下载在跑。
2. **速率**：当前只有累计量，没有瞬时速率（KB/s）；有了逐秒采样即可算出。
3. **动态转发的 SOCKS5 认证**：服务端握手目前只接受"无认证"（监听在环回上，本机进程即可用）。
   若将来支持绑到 `0.0.0.0`，应同时要求用户名/口令认证。
